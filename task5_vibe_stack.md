Тестовое Polza Agency, задача 5

1) IDE и модели — сейчас и за полгода

Сейчас почти всё через Cursor. Агент видит репозиторий, терминал, диффы — меньше копипаста из браузера. Основная модель для кода и ресёрча — Claude; на мелкие правки иногда более быструю/дешёвую внутри Cursor.

Полгода назад: VS Code + ChatGPT/Copilot. Схема была «спросил → вставил → полчаса чинил». Cursor этот цикл укоротил. Claude Code / терминального агента включаю, когда надо прогнать длинную пачку правок без кликов по UI. ChatGPT оставляю для черновиков, но холодные письма всегда вычитываю сам — иначе сразу слышно шаблон.

2) Подписки

Для нормальной работы хватает:
- Cursor Pro (или аналог с агентом)
- одна сильная LLM-подписка (Claude или ChatGPT)

Apollo/Instantly — уже не LLM, но без них аутрич-стек хромой. Третью AI-подписку беру только если упираюсь в лимиты или нужен отдельный API под скрипты. На одном бесплатном чате 3–6 проектов параллельно не вывезти.

Рутину (CSV, регулярки) гоняю на дешёвой модели, персонализацию и письма — на дорогой: там цена ошибки выше.

3) Как сравниваю модели/инструменты

Не «на ощущениях», а на одном мини-наборе из работы:
1) вытащить с сайта 1–2 факта без выдумок
2) написать письмо 1 так, чтобы не пахло ChatGPT
3) починить скрипт по кривому CSV
4) найти баг в готовом коде
5) поймать ловушку в таблице (чужой домен, мёртвый сайт, B2C)

Смотрю: сколько правок руками после ответа, врёт ли фактами, как держит русский B2B, скорость и цену прогона. Красивый текст с выдуманным кейсом для нас хуже скучного, но честного.

4) Тесты на новую функцию

Минимум:
- юниты на нормализацию URL/домена/email и дедуп
- 3–5 HTML-фикстур: нормальный сайт / пустой / JS-заглушка / 404
- контракт выхода: нужные столбцы, UTF-8, исходник не затираем
- негатив: пустой input, битый CSV, таймаут
- если трогаем отправку/API — только dry-run

Отдельно: персонализация не имеет права додумывать. Лучше пустой сигнал + флаг QA, чем красивая ложь.

5) Разрешения coding-агенту (терминал + база)

По умолчанию: читать проект, тесты/линтеры, локальные скрипты, venv, писать в data/out.

Без отдельного «ок»: rm, hard reset, force push, .env/ключи, прод-CRM/Instantly/почта, миграции в бой, скачивание левых бинарников.

Клиентская база — только копия. Всё, что может начать рассылку или массово менять статусы — только после ручного просмотра команды.

6) Автотесты и CI/CD

На одноразовый ноутбук — нет. На пайплайн, который пойдёт в бой (обогащение/персонализация) — да.

Перед merge: линтер, тесты, проверка что секреты не в коммите, для data-скриптов — прогон на фикстуре и схема столбцов.

Перед запуском на клиентской базе: dry-run на 10–20 строках, смотрю ошибки сети/парсинга, глазами 5–10 персонализаций, output в новый файл (исходник не трогаем).

Коротко: вайбкодинг для меня — ускоритель цикла гипотеза → скрипт → проверка → правка, а не «пусть модель сама». В аутриче цена ошибки — репутация домена и доверие клиента.
